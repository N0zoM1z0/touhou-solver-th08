# TH08 Counterexamples CE-0270–CE-0319

## CE-0270 — Offline beam replay used the wrong hazard epoch

**2026-08-26; audit-infrastructure bug fixed offline.** Live decisions retain
observation-to-input age separately from player-to-hazard lag and the complete
discrete bullet-age support. `local_beam_stability_audit.py` instead supplied
the observation age as local `snapshot_lag` and omitted bullet-age support.
After the source-authoritative bullet clock correction this replayed a
different geometry root while presenting it as a same-row policy comparison.

Resolution: the flat planner wrapper now accepts the explicit bullet support;
the audit reads both local clock values from `hazard_alignment` and fails
closed if either is absent. An eight-root replay of the corrected-age Easy
trace matches all eight recorded actions. One same-action hard vector still
differs at frame 57590 (`6` versus `3` accumulated collisions with essentially
identical penetration), so exact same-row hard-vector reproduction remains an
open diagnostic rather than a claimed policy result.

## CE-0271 — A scan counter was mistaken for current pool occupancy

**2026-08-26; unsafe shortcut rejected, source-layout bug fixed offline.** The
live synchronous prefix read starts at historical `ENEMY_POOL_BASE`, which the
authoritative manager layout proves is `enemies[1]`. Native slot zero arrives
only through the roughly 91 ms asynchronous sparse scan or the boss guard, and
that sparse worker is resubmitted every four game frames. Merely deleting it
would leave an uncertified tail and stale slot-zero geometry.

The first proposed resolution compared prefix active flags with
`EnemyManager::EnemyCount`. Source inspection falsifies that certificate:
`OnUpdate` resets the field immediately before the ascending scan and
increments it before updating each encountered active slot. An encountered
enemy can die later in its update, while an ECL child can occupy a lower slot
after that slot has already been scanned. Equal counts can therefore be
offsetting and do not prove tail absence.

Resolution: the generic `source-contiguous` profile reads native slots 0--63
synchronously and retains complete slots-0--479 background coverage, replacing
the scalar scan with one contiguous 10.3 MiB read into a reusable buffer. Easy
selects the existing local-only path when ordinary global authority is off,
but still owns the background enemy worker. The old trace's maximum serialized
body slot is 32; this is workload evidence only. Physical latency and survival
effects remain unclaimed pending a Wine benchmark and complete Easy route.

## CE-0272 — Structural online wiring could starve, widen, or use the wrong clock

**2026-08-27; inferred from code/state-machine review and fixed before physical
promotion.** Four independent defects prevented the first Linux online hookup
from being called hard action authority. First, the historical corridor holds
one selected action for all eight frames in a layer, while the new controller
could choose again on the next physical frame. Consuming only that layer's
first action discarded the macro-action premise. The online hard recurrence is
now 4 px, includes the 2.828 px cell radius, and has exactly one physical frame
per layer.

Second, the old flat `choose_action` wrapper forwarded an allowed set without
its authority name, leaving coarse viability relaxation enabled. A locally
empty intersection could therefore widen a named global set. The wrapper now
forwards the name and every named authority is non-relaxable; a deterministic
locally conflicting singleton regression retains the named action.

Third, every quick rolling solve could replace an earlier pending policy with
a later source epoch. With a lead of 80 frames and sub-lead solve time, the
pending boundary would advance forever and no policy would become queryable.
The earliest completed policy is now preserved, new submission is suppressed
while it is pending, and a regression advances it to active at its exact epoch.
A real H80/one-frame solve and exact version join also produce a nonempty named
action set in the online planner test.

Fourth, policy staging, age, future offset, and query had all used
`enemy_manager_frame` even though the wire action is addressed by input epoch.
This violated the existing physical-frame contract. Authored source provides
two opposing mechanisms: `EnemyManager::OnUpdate` returns before incrementing
its timer when GameManager flag bit `0x400` is set, while ECL callback 26 can
set `g_EclScriptedGlobalUpdateFreeze`, suppressing bullet motion and individual
enemy timers without necessarily suppressing the manager-timer increment.
The manager counter is therefore not an unconditional physical or hazard
clock.

The online root now captures its source input epoch, dialogue predicate, and
scripted-freeze byte. A separate cadence authority requires two safe roots
with equal positive input/manager deltas, binds each corridor manager source
frame to an explicit source input epoch, and checks that affine mapping at
pending activation and every active query. Context/gate/delta changes advance
a generation and reject older asynchronous future/corridor work. Deterministic
regressions cover certification across skipped publications, unequal-delta
revocation/recovery, dialogue/scripted-freeze/manager-skip fail-close, capture
attachment, and active-policy revocation.

The ordinary future-source interpreter already fails closed on any reached
unsupported immediate callback; only indices 12/14 are geometrically modeled
and 13 is inert, so the freeze-writing callback 26 cannot occur inside a
projection advertised complete. This supports the transitional cadence gate
but does not prove every not-yet-observed dialogue/scene transition.

**Remaining falsifier:** this establishes structural and clock-safe delivery
only inside the certified unit-cadence interval. Retained
`8/12/8` foreground timing is 17.72 ms mean / 32.17 ms p95, while the current
action edge certifies one frame. A connected deadline miss repeats the held
mask without a finite fallback lease, so a miss-bearing run is telemetry, not
hard-safety promotion. No gameplay process was started for this checkpoint.

## CE-0273 — Online producers still required a stopped-root-sized observation

**2026-08-27; physically observed integration failure, unresolved.** The
non-blocking runtime and dual-clock gate ran continuously for a bounded 3,600-
observation Easy Stage-1 diagnostic. Runtime ECL identity was accepted and
2,866 observations were clock-certified with zero cadence mismatch, but all
574 future-source submissions were rejected. No future root completed, no
corridor was submitted, no policy was queried, and no global action constrained
the local planner. Every retained on-time row withheld scale authority as
`root_only_source_inventory_unknown`.

This falsifies the assumption that moving the historical future/source work to
a background thread was sufficient to make it an online producer. The future
capture still brackets a roughly 10 MiB enemy/source observation plus
supporting reads with unchanged manager/update-serial clocks. The Stage 1--5
no-scale-writer authority also performs a complete source inventory
synchronously in the foreground until it binds. Under continuous cadence the
background bracket never completed, while foreground transactions missed their
target epoch: the run recorded 1,205 stale captures, 2,424 stale plans, and a
4,341 native deadline-miss delta. Only 1,176 gameplay actions were sent on
time, all `stay`; seven hits followed, with the first at manager frame 1,429.
No Bomb bit appeared.

The exact future exception and scale-capture subreason were not retained, so
the stable-bracket mechanism is inferred from the implementation plus the
aggregate statuses, not promoted as an exception-level trace. The missing
subreason and maximum consecutive held-fallback length are telemetry defects.

Correction boundary: do not tune lead/interval or call this physically wired.
Publish a compact immutable post-update source root/certificate from the
runtime (or an equivalent double buffer), remove all large source inventory
from the foreground action path, and make both immediate and background tiers
consume that version. A future physical Gate 1 again requires nonzero future
completion, corridor publication, query, and constrained action counts.

Physical authority and compact evidence:
`notes/runs/easy_linux_online_gate1_20260827.md` and
`artifacts/runtime_reports/easy_linux_online_gate1_20260827.json`.

## CE-0274 — A packed root can still hide a foreground full-pool scan

**2026-08-27; statically observed implementation defect, corrected but not
physically validated.** The first protocol-v3 adapter copied only active native
records, then reused the historical decoders by zero-filling and traversing
the complete 1,536-bullet, 256-laser, optional 2,096-item, and 480-enemy slabs
inside `LinuxHazardCapture.capture`. That removed the large cross-process read
but did not satisfy the stronger requirement that the foreground action path
own no large scan. It would also have made a favorable transfer-time result
misleading because Python still paid full-pool materialization and traversal.

Correction: the immutable reader now exposes validated typed fixed-pool
records with original slot indices. The immediate decoder consumes those
records directly. Full zero-filled compatibility slabs remain available only
to the historical future-source decoder on its background worker. Runtime ECL
identity and first scale-source binding are background tasks over the same
immutable generation. A deterministic regression supplies a reader whose
`read_into` raises and proves immediate capture succeeds without a full-pool
read; compact/full bullet decoding also agrees for the same active record.

During the same review, an indexed-enemy registry edge was found: timeline
inventory dereferences two fields even when a non-null registry pointer names
an inactive slot. Sparse reconstruction would have replaced those stale native
bytes with zeros. The runtime now packs those exact fields separately and
fails snapshot construction if the pointer is outside the known enemy/spell
owner layouts.

This closes representation and version-sharing defects in code. It does not
show that runtime packing, the single process copy, Python decode/plan, or
release traffic meets 60 Hz. No game was started. The retained design and
falsifiers are in
`notes/architecture/TH08_LINUX_IMMUTABLE_ROOT_20260827.md`.
