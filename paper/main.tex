\begin{abstract}
We study hard no-bomb autoplay for the Sakuya/Remilia Lunatic Route~2 of
Touhou~8.  The objective is empirical survival, not cross-game or cross-route
generalization.  A reconstructed, function-matched code base makes exact
collision, update, emission, and scripting semantics available, while the
shipped executable and isolated Wine observations remain the physical
authority.  Our principal finding is architectural: more compute cannot help
when strategic jobs are never submitted, and exact collision geometry cannot
improve survival when sensing and issue latency push the realized control
delay outside the planner's support.  We therefore separate source-exact
world projection, parallel long-horizon viability, short-horizon robust
control, and fresh input publication.  Unsupported future producers become
\unknown{} rather than silently safe.  The design is generic first; a
stage- or spell-specific adapter is admitted only after practice and full-route
evidence falsifies the shared kernel or policy.  A replayable source-stateful
stage laboratory and an independently compiled C oracle now exercise this
boundary over long, pool-saturating histories before Wine is used.
\end{abstract}

\section{Objective and Evidence Discipline}

The target is completion of one fixed route with as few native hit edges as
possible under a hard no-bomb policy and a no-life-decrement patch.  The patch
permits complete-route measurement but does not erase the causal effect of a
hit: power loss changes damage, phase duration, and all later state roots.
Consequently, route totals are global outcomes rather than independent Bernoulli
trials.

We distinguish three kinds of evidence.  Functions marked as exact matches
define engine semantics.  Runtime roots provide RNG, VM, player, enemy, and
phase state that static source cannot infer.  Complete isolated Wine routes
validate latency, input, cleanup, and aggregate survival.  A model receives
action authority only over the intersection of these claims; everything else
may run in shadow for measurement.

\section{Failure of the Previous Architecture}

The historical solver combined a ten-frame local beam with a nominal
eighty-frame corridor solver.  In the retained complete routes, however, every
corridor submission was blocked by time-scale provenance, so no worker job or
global policy query existed.  The VPS therefore accelerated neither strategy
nor future avoidance.

Promoting the source-correct $1\times1$ player half-extents and inclusive
binary32 AABB predicate exposed a second defect.  The old inflated radius was
an accidental safety margin.  In the first complete promoted route, hit-row
control delay and observe-to-input latency rose sharply, especially in Stage~5,
and many realized delays exceeded the modeled upper bound.  The correct
response is not to restore false geometry: physical occupancy and uncertainty
about when that occupancy was observed or controlled must be represented as
different quantities.

\section{Hierarchical Solver}

The proposed generic pipeline has five layers:

\begin{enumerate}
  \item \textbf{Coherent runtime root.} Capture the stage-selected ECL image,
  main and child VMs, RNG, emitters, enemies, bullets, lasers, player movement
  state, time scale, and input transaction state under explicit frame brackets.
  \item \textbf{Source-exact forward kernel.} Execute only reached scripting,
  emission, transform, lifecycle, and geometry paths using binary32 update
  order.  An unsupported reached dependency terminates coverage with
  \unknown{}; it never means ``no hazard.''
  \item \textbf{Versioned hazard field.} Merge current entities and future
  births into occupancy intervals.  Physical hitboxes remain exact while
  capture-span, root-age, transform, and control uncertainty are separate
  envelopes with separate provenance.
  \item \textbf{Parallel global viability.} Native workers compute a
  time-expanded backward winning set and escape-volume values.  Work is
  partitioned by time slabs or independent root hypotheses and published only
  when all required versions agree.
  \item \textbf{Robust local issue.} A short-horizon controller intersects the
  global winning actions with all active/held/pending input-delay hypotheses,
  then performs a bounded fresh recertification before publishing input.
\end{enumerate}

For root $r$, action $a$, and delay hypothesis $d$, hard action authority is

\[
  A(r,a) = E_{\mathrm{root}} \land E_{\mathrm{scale}}
  \land E_{\mathrm{births}} \land E_{\mathrm{geometry}}
  \land \bigwedge_{d\in D} E_{\mathrm{prefix}}(r,a,d),
\]

where each term includes a semantic version and a covered frame interval.  A
cached global solution is advisory when its scale, birth, geometry, or policy
version differs from the current root.

\section{Using the VPS}

The main controller is latency-sensitive and should not perform long global
search under the Python GIL.  Immutable capsules are sent to low-priority
native worker processes pinned away from the Wine sensing/issue core.  Workers
preallocate geometry buffers and reuse spell-independent transition tables.
The global horizon may scale with available cores; local issue latency may not.
Throughput, queue age, coverage, and publication compatibility are recorded
separately so that ``many CPU cycles'' cannot be confused with useful action
authority.

A controlled future-only Stage~5 solve confirms both the benefit and the
limit.  Geometry time falls substantially from one through sixteen workers,
but rises again at twenty-four and thirty-two while the viability tensor stays
identical.  The experimental thirty-two-worker limit was therefore reverted.
Surplus cores are better spent on independent retained roots and differentials;
the latency-sensitive controller retains its smaller worker allocation.

\section{Source-Stateful Offline Laboratory}

The previous synthetic tests mutated snapshots.  Such a frame can look
plausible while having no legal causal history: pool occupancy, RNG position,
callback selection, transform timers, and phase clears need not agree.  The
replacement fuzzer generates an immutable stage program and executes its
state forward.  The program contains contiguous phases, resolved direct-fire
descriptors, one shared gameplay RNG root, callback and laser events, and
explicit transform queues.  The runtime retains the native 1,536-bullet and
256-laser limits and the source update order.  It then drives the ordinary
Sakuya/Remilia local planner through configurable sensing and issue queues
under a hard no-bomb assertion.

This laboratory uses a deliberately narrow exactness boundary.  A resolved
descriptor is treated as the output of an ECL or timeline producer; the
runtime is exact only from that point through the supported pool, RNG,
callback, transform, isolated spawn-lifecycle, and geometry paths.  The
future-birth lowerer and complete-stage runtime share the type/flag contract
for all 21 source-selected state-2/3/4 spawn rows.  Native spawn state is kept
separate from callback phase state.  The retained-source executor additionally
models the generic 480-slot enemy pool, timeline and ECL constructors,
synchronous child bootstrap, and the lowered child-VM subset.  Composition of
spawn lifecycle with callbacks/transforms still fails closed, while ECL beyond
that lowered subset, general ANM execution, and unsupported callbacks remain
\unknown{}.  Hence unbounded seeded
composition gives broad transition and
pressure coverage without claiming that a generated stage is a particular
shipped spell.

A reduced C oracle is tracked with the solver and compiled independently of
the Python model and optimized planner.  It transcribes bounded recovered
kernels for RNG, all nine direct-fire modes, the generic state-2/3/4 spawn
lifecycle, callback~12, inclusive AABB, and eight transform handlers.
Complete-stage lockstep requires exact discrete
state and RNG agreement; every reached spawn-lifecycle bullet is also replayed
by the C kernel from its original root.  Only bounded
\code{sinf}/\code{cosf} versus Python libm drift is admitted.  Capsules are
canonical JSON with a source revision and SHA-256 identity, so a failing long
history can be replayed and delta-debugged after the generator changes.

\section{Generic First, Specialization by Evidence}

One ECL/timeline/emitter kernel, one bullet/laser stepper, and one viability
solver are the default.  Source-derived stage tables may select an ECL image,
reachable opcode subset, producer cache, or horizon without changing semantics.
A hand-written stage or spell policy is justified only if both conditions hold:

\begin{enumerate}
  \item practice-mode replay repeatedly identifies a residual failure after
  generic coverage and timing gates pass; and
  \item the special rule is derived from a stable source/runtime invariant and
  remains safe at the lower-power roots observed in full routes.
\end{enumerate}

Practice mode is therefore an efficient localization tool, not the promotion
criterion.  Its full-power damage shortens phases and can hide survival
failures.  Every specialized candidate must be replayed with low-power or
power-branched roots and finally in the complete route.

\section{Preliminary Results and Interpretation}

A shadow-only route with the old live collision behavior completed with 57
hits.  The first route after promoting exact bullet/body AABBs completed with
93 hits.  This does not falsify the source geometry: runtime player boxes were
stable at $1\times1$, and large differential tests matched the source predicate.
Instead, the promoted route revealed a latency--policy feedback loop.  Stage~5
hit-row delay frequently exceeded the configured model, long local
recertification delayed input, hits reduced power, and the changed future root
created more difficult exposure.  Cross-frame bullet-pool capture existed but
covered only a minority of hit windows, so it is a correctness fix rather than
a sufficient explanation.

The global result is unambiguous: numerical scale horizons were present on
every decision, but hard scale provenance was absent; a Final-B static image
was compared once against the Stage~1 runtime image and never retried, and
future hostile-birth coverage remained unknown.  Thus global worker count was
zero in effect despite four configured workers.  The next experiment first
repairs route-wide identity and shadow delivery, then adds complete producer
coverage before granting control.

The first repair was established entirely offline.  A stage-indexed catalog
pins each decoded ECL image and its scale model; static control-flow inspection
classifies both Stage~4 branches and Stage~5 as free of scale callbacks.  The
runtime identity observation was moved from post-issue to the stable pre-plan
root, and the global decision clock was separated from the stage-local enemy
manager clock used to bracket active ECL VMs.  An exact Stage~5 integration now
publishes a complete finite unit-scale schedule on its first transaction.
This closes only a prerequisite: solutions without a matching complete
future-birth version remain shadow-only.

The next offline gate found a stronger publication defect.  Active-spell
policies inherited action authority from the time-scale certificate even when
the job contained only currently observed entities.  We replaced the separate
metadata checks with one content-addressed join over the solver root, runtime
ECL image, scale schedule, future-hazard projection, collision geometry, and
policy configuration.  The consumer requires the complete projection to span
the policy horizon and requires every retained coverage slab to carry that
same version.  Deterministic negative tests independently perturb each member;
all become shadow-only.  A re-rooted schedule remains compatible when both
schedules are exact complete unit-scale consequences of the same pinned
source.  This gate prevents false global authority but does not manufacture
the still-missing spell producers.

Mode identity is itself part of that prerequisite.  Source inspection and an
exact physical identity check showed that Practice Start, like route play,
loads \texttt{ecldata*.ecl}.  The loader selects
\texttt{ecldata*sp.ecl} only when the distinct Spell-Practice flag is set.
An intermediate catalog confused those two flags; its exact identity gate
failed closed before planning, exposing the error without granting authority.
The corrected catalog preserves a separate Spell-Practice image only for
static cross-package analysis.  A retained Stage~5 trace further shows
complete 256-frame callback-12 schedules for every
decision in spells 103, 107, and 111, but callback-14 control remains unknown
for 721 of 732 spell-115 decisions.  This shifts the immediate target from a
wider callback-12 scan to future bullet births and child VMs, with callback 14
as an additional spell-115 dependency.

A static producer contract then normalized subroutine identifiers and phase
exit targets across the route and Spell-Practice Stage~5 packages.  All five
route spell programs have identical normalized dependency graphs in the
Spell-Practice image.  For the four
observed cards, the graph contains respectively 6/3/3/6 direct-fire sites,
0/3/0/3 transform sites, and 1/3/13/2 child-spawn sites.  These counts are a
coverage denominator, not predicted multiplicities: only a retained VM root
can resolve loops, locals, RNG, and reached branches.  Consequently the
offline executor may consume a supported causal prefix but must stop before an
unlowered child or callback boundary.

The first reached-prefix implementation removed an artificial restriction:
the shared VM had rejected a root merely because its spell identifier was
active.  The controller now admits such captures but joins them to planning
only when the captured and current spell identifiers match exactly.  Source
operand \texttt{0x2762} is also lifted to the conservative native
\texttt{float32} random-angle interval, including endpoint rounding.  A
source-exact synthetic spell-103 VM root consequently closes the global
horizon before its first birth; a longer query stops at the tagged birth that
callback~12 will later transform.  This locates the next missing semantic
without weakening the unknown boundary: callback-tagged future trajectories,
not spell metadata or random-variable syntax, now gate global authority.  No
physical result is attributed to this offline checkpoint.

A subsequent isolated Stage~5 acquisition supplied the missing physical
roots.  It completed the stage without an outer-timeout or prefix-isolation
failure and retained content-addressed capsules for the four cards actually
visited by the selected route (103, 107, 111, and 115).  Two asynchronous jobs
completed during player phase~3 and exposed a sampling defect: a stale spell
identifier could consume a card's bounded quota even though the root was not
planner-eligible.  Completion now rechecks route, difficulty, stage, spell,
player phase~0, and bomb inactivity before persistence.  The transition roots
remain useful fuzzer states, while the phase-0 roots localize the next unknowns
to singleton auxiliary-callback semantics and type-16 template/ANM geometry.
All projections remain shadow-only; the run's hit count is therefore not an
algorithm comparison.

We next connected these capsules to the long-stage laboratory through a
generic resolved-event adapter.  The adapter verifies the capsule and ECL
identity, replays the reached producer, and admits only point-valued,
flag-free direct-fire descriptors.  It preserves the producer's resolved aim
instead of reevaluating aim at an unrelated offline player state, and it never
uses an interval midpoint.  A whole-root \unknown{} yields no stage program;
a later causal \unknown{} permits only the preceding proven prefix.  The
physical capsules currently exercise these rejection and prefix rules but
contain no admitted hostile birth, so they cannot yet change a global winning
set.  This sharpens the next experiment to generic ANM lifecycle and template
geometry, rather than a spell-specific policy adjustment.

That experiment first exposed an observer error rather than a difficult card
rule.  The native initializer constructs 21 bullet-template rows, whereas the
capture projection retained only 16.  We derived a compact, type-indexed
contract from the pinned source and the exact shipped \texttt{etama.anm}; an
old capsule may receive its missing suffix only when all 16 observed rows and
their native layout metadata match that contract exactly.  Same-capsule replay
then moved the first unknown at future frame~87 from absent type-16 geometry to
the genuine callback-14 tag, while retaining the same empty 86-frame proven
prefix.  This is semantic progress, not a survival result.  The derivation
also falsified a global ten-update spawn assumption: state-2 completion is 10,
24, or 30 updates depending on bullet type, with separate state-3/4 profiles.
Bullet type now survives the producer IR, and one generic type/flag selector
reproduces native flag priority, divided pre-activation motion, and same-update
state-1 activation.  An independent C sweep spans all 21 types and seven
no/singleton/mixed flag classes.  It exposed a second geometry bug: an ideal
binary64 trajectory plus fixed $2\times10^{-5}$ guard lost 392 of 420 lethal
samples, with maximum axis error about $8.18\times10^{-4}$.  Replaying each
source-order binary32 operation with an outward-rounded interval contains
every C point in the AABB path.  The compact sector instead preserves the
shared speed/angle parameter and analytically propagates an error term for
each float32 operation, including a speed-scaled trig-component bound.  A
256-root random speed/angle differential also remains contained, while this
formulation makes the 1,536-birth stress about 7.9 times faster.  These
lifecycle facts remain shadow-only because the retained root still reaches
callback~14 before any admitted hostile birth.  Native child/timeline
scheduling now reaches that same semantic boundary; callback~14 and transform
composition are the next generic closure steps.

We then carried that contract into the complete-stage runtime rather than
leaving it as an isolated future-envelope result.  A versioned schema retains
the native type and spawn flags without changing earlier capsule identities;
malformed operands and unaudited lifecycle/callback/transform compositions
fail closed.  A 3,600-frame gate reached pool capacity, activated 18,665 spawn
lifecycles, and made 120 calls to the real local planner.  Across 1,412,926
reached lifecycle samples, the independent C state and position matched
exactly.  The observed 152 cooldown-normalized collisions describe the newly
generated hostile capsule and are not a native hit metric.  Only compact
metrics and the report hash were retained, preventing routine successful
trajectories from becoming a growing artifact corpus.

Integration also falsified a second implementation: the real local hazard
projector recognized only state~2 with one observed completion timer, advanced
states~3/4 at full speed, and treated all preactivation states as immediately
lethal.  The copied normal ANM VM already present in each pool record exposes
its script index; the 21 source template rows use distinct normal scripts, so
type recovery adds no sensing call.  Local collision semantics now use the
shared type/state table and admit only state~1 with callback auxiliary state
zero.  Starting every type and state~2/3/4 class at multiple preterminal ages,
four-step position, state, and lethal membership match C exactly.  The
3,600-frame outcome remained 152 normalized collisions and the same final
position, so this repair is not counted as a policy improvement.

The first child-birth closure separates three states that an approximate
model can easily conflate: the spawning parent, the copied manager template,
and the child after its synchronous ECL bootstrap.  One generic opcode table
covers constructors \texttt{0x5A}--\texttt{0x5E}.  Source inspection shows
that the linked-child suppress bit belongs to the parent, while link,
collision, character-side, and follow-position writes occur only after the
child bootstrap succeeds.  The follow constructor overwrites the resulting
child relative position and then recomputes world position; it cannot assume
that the bootstrap left either field unchanged.  A separate C transcription
matches the Python transition for all five families and their guard branches.
The integrated executor now instantiates the source-initialized template,
allocates the first free native slot, installs it before recursive bootstrap,
and then follows the manager's ascending scan.  Therefore a child born above
the scan cursor receives its ordinary update in the birth frame, whereas one
born into an already scanned lower slot does not.

This integration exposed two state-projection errors.  The native
\texttt{SpawnEnemy2} copy spans VM bytes \texttt{+0x18} through
\texttt{+0x8f}; the old capture ended at \texttt{+0x67}, omitting spawn and
call parameter arrays used by real child roots.  The versioned capture now
retains the full \texttt{0x90}-byte prefix, while old capsules fail closed if
execution reaches an absent operand.  Separately, an affine angle-to-player
tag is meaningful only for one source and one RunEcl update.  Preserving it
across a frame boundary or copying it from parent to child caused causal
conditioning to substitute the wrong player/source geometry.  The executor
now retains the value interval but forgets that obsolete correlation.  A real
Stage~5 subroutine-63 constructor consequently bootstraps subroutine~64 and
reaches its first tagged bullet birth without a stage or spell branch.

Source inspection then corrected the interpretation of that boundary.
Descriptor bit \texttt{0x100000} is a callback filter tag, not a movement
operation; bit \texttt{0x200} requests only spawn sound.  Immediate callbacks
12 and 14 scan the fixed bullet pool and test the filter against an ECL integer
local, while callback 13 changes only background tint.  Direct fires and these
callbacks now share one ordered action stream, so only a matching callback
after an allocation composes with its birth, including same-frame pool order.
The first consumer uses a conservative full-direction disc at the largest
base or callback speed and keeps exact spawn-ANM activation.  Standalone
callbacks are retained separately because they can mutate bullets already in
the root snapshot; their presence explicitly blocks current-pool composition
authority.  Thus this remains semantic progress rather than a route-hit claim.
The callback-14 scalar transition is independently transcribed in C and
differentially checked across all three source branches.  In particular, its
phase-zero branch changes phase only, a detail that cannot be recovered by
treating callback 14 as a parameter-reduced callback 12.  Scheduling this
kernel against the sensed pool remains a separate, explicitly gated join.

The bounded pool composer now makes that join explicit rather than implicit:
it takes the bullet snapshot's offset from the source root, rebases only the
strictly future callback suffix, and composes equal-frame transitions before
native movement.  It emits velocity and collision schedules for the existing
hazard recurrence and agrees for packed and materialized pools.  Uncertain
frame alignment, set-valued operands, transform interaction, or an existing
schedule produces an incomplete result.  Consequently the remaining
integration problem was a clock-and-identity proof, not another callback
dynamics model.

That review found a separate global-layer error before the clock join was
enabled.  The corridor bullet protocol omitted native state, state timer, and
template type, so states 2--4 were treated as immediately lethal ordinary
motion even though the local projector already modeled their spawn ANM.  The
global adapter now merges type-selected divided motion, the terminal
divided-plus-full update, callback replacements, and collision activation into
a sparse trajectory.  All template/state classes and 256 seeded callback
histories agree in lethal membership with the C-locked local recurrence, with
binary32 centers contained by explicit uncertainty.  The geometry identity is
versioned anew; no result computed with the old recurrence can gain authority.

Finally, callback scheduling is represented as a three-clock-and-scale
certificate.  It binds the projection digest and root, a point-valued
bullet-pool root, exact binary32 scale, the policy source and complete horizon,
and the resulting composed pool.  A
capture that spans an update is rejected when callbacks exist, because slots
could straddle the transition.  The solved artifact now stores the immutable
join version while a separate runtime handle retains the concrete certificate.
The global root hashes it beside the composed pool, and both the worker and an
independent authority assessor verify projection, bullet, and policy clocks.
The controller constructs this object from the raw sensed pool only under an
exact unit-scale schedule and a zero-span capture.  Incomplete composition
therefore consumes no worker slot.  It also postpones the bounded pool scan
until a submission is due and a worker slot is free, avoiding composition
latency on intervening local decisions.  This closes offline global integration,
not physical promotion: the lane remains default-off and has not yet changed a
retained-root winning set or a Wine action.

The integration also enforces an important layer boundary.  A certificate
rooted at the worker's old bullet snapshot cannot justify a later local prefix
over newly sensed bullets.  Local and delayed certificates continue to reject
such a future until they perform a fresh current-frame join.  This distinction
prevents a correct global artifact from becoming stale local authority.

The complete-stage laboratory then exposed several errors that short
geometric fixtures had not revealed.  Callback-12 motion was modeled while
its auxiliary non-collision state was omitted, and future frames shared a
mutable auxiliary-state buffer, allowing a later callback to rewrite earlier
history.  The gameplay RNG rounded after a double-precision division rather
than casting the numerator to binary32 first; exhaustive first-step testing
disagreed on 62,784 of 65,536 roots.  Finally, random pattern parameters were
sampled before pool allocation, whereas the source allocates first and
consumes no RNG for the suppressed tail of a full pool.  These corrections
matter because each error shifts a long future globally, even when its
single-frame geometric displacement is small.

An earlier extreme generated program completed 12,000 frames, repeatedly filled all
1,536 bullet slots, and exercised more than $10^5$ transform transitions.
This is evidence that the harness can apply pressure beyond a normal Lunatic
stage while retaining finite-pool semantics.  It is not survival evidence:
the current normalized collision count is an offline same-capsule metric, and
the generator begins after producer resolution.  The retained-root importer is
now connected through lifecycle, child/timeline birth, conservative ordered
birth composition, and exact bounded callbacks against the already-sensed
pool.  The next causal experiment asks whether this future changes a same-root
global winning set; if conservative birth discs or an unresolved transform
destroy viability, only that first reached boundary is tightened before any
physical route is launched.

Attempting that experiment exposed an observational-contract error before a
planner result: the existing physical Stage~5 capsules retained producer state
but not their same-clock current bullet and laser pools.  Their future-only
geometry changes the number of viable states, but cannot be paired honestly
with another sensed pool.  Explicit retention now stores canonical active
hazard slots inside the same manager/update bracket and requires every root
clock to agree.  A long generated-stage root round-trips hundreds of bullets,
lasers, lifecycle state, and active transform runtime to the identical global
viability tensor.  This makes a fresh physical capsule sufficient for offline
planner replay without retaining multi-megabyte raw slabs.

Review of that compact record found that its nominal transform runtime was in
fact only the stop/turn union and one pending record.  The revised retained
root stores the exact 18-record, 432-byte program, queue and offscreen state,
and the timer/parameter block for every currently active handler.  Inactive
union bytes are omitted rather than granting authority to uninitialized
floats.  This richer state is decoded only for retained or due global roots;
the packed local sensing path remains unchanged.  Thus source fidelity does
not require interpreting the program inside the 16-ms issue loop.

The same experiment found a more important model falsifier.  The old global
adapter treated every active transform as constant velocity plus a linearly
growing uncertainty margin.  In a fixed generic stage, more than half of the
identity-preserving transform samples leave that margin; the worst H80 center
error is over three times its claimed bound.  Geometry version~4 therefore
records transform completeness and forbids action authority for such a pool.
This fail-closed change is not the solution: the retained ordered native
transform program must execute before transformed current bullets regain
authority.  We implemented a readable binary32 Python reference and a
separately compiled C transition over one flat state.  Long independent
histories cover queue admission, immediate records, shared handler blocks,
source-order motion, wraps, movement, and visual-geometry culling; template
replacement and derived finite-pool births stop with typed unknowns.  The
differential also found a language-boundary error: comparing native
$\mathrm{float32}(0.99)$ with a Python binary64 literal selected the wrong
timer branch exactly at the source threshold.

The pool-size experiment changes the architectural conclusion.  At 1,536
states, one persistent native transition takes 0.02446 ms median (about
62.8 million state-frames/s), making an 80-frame transform rollout roughly
1.96 ms of kernel work.  Python-object preparation and decoding dominate:
the composed one-frame wrapper takes 22.233 ms, versus 70.778 ms for the
scalar reference.  More CPU therefore helps only after representation is
fixed.  The global worker should own a persistent flat batch populated from
packed sensing and emit compact planner geometry; reconstructing every bullet
as a Python object per horizon frame cannot enter the 16-ms issue loop.

A route-work audit also exposed avoidable serial work inside the fresh issue
layer.  Almost all changed-prefix transactions ultimately preserved the
already selected, freshly safe action, yet the implementation recomputed all
17 independent action branches before publishing input.  We replaced this
with an exact lazy transaction: certify the selected and optional preferred
actions first, and compute the remaining branches only when those proofs do
not determine the historical selection; fallback recomputes the complete
historical batch.  Uncomputed actions are explicitly
absent rather than presumed safe.  A dense synthetic differential preserves
the selected certificate bit-for-bit while reducing median recertification by
more than an order of magnitude; focused and complete-route physical gates are
still required to establish survival benefit.

The first focused physical gate refines that result.  In a complete Stage~5
Practice attempt, 88.28\% of changed hostile-prefix transactions terminated on
the exact lazy proof; that mode took 3.97/6.99 ms median/p95.  The remaining
351 transactions required the unchanged exact full fallback and took
62.45/76.42 ms.  Spell~107 produced 300 of those fallbacks, 12 of the 28
observed hits, and a 13-frame p95 decision cadence.  Thus laziness improves the
common path but cannot bound worst-case control delay when the selected action
is genuinely unsafe.  The next generic problem is to share or native-batch the
complete action/delay computation, not to presume an untested action safe.

This gate also exposes an infrastructure mismatch with the intended VPS
architecture.  Corridor, audit, enemy-sensing, and future-source services are
currently thread executors in the same Win32 Python process.  A controlled
foreground-versus-thread/process benchmark is needed before assigning causal
latency, but the implementation does not yet provide the process and affinity
isolation assumed by our parallel-search design.

The first complete Easy route also supplied a clean beam-pruning falsifier.
Near the Stage~4 bottom-right boundary, width 24 spent every slot on minor
continuations of the wrong first actions, although a collision-free
\texttt{left\_fast} family survived at width 256.  Label-aware deduplication
alone did not recover it.  The corrected reducer reserves one leader per first
action inside the best non-tradeable hard class, but activates this diversity
only when one held action can consume the remaining boundary distance.
Interior roots therefore keep ordinary global top-$k$.  At the two causal
roots, the gated width-24 search matches width 256 while requiring roughly one
quarter of its solve time; a bounded route replay found no hard-vector
regression among changed actions.  The native interface versions this behavior
explicitly rather than silently changing the old reduction ABI.

Closed-loop stage fuzzing then revealed why pruning could not be selected by
synthetic hit count alone.  The generated runtime owned exact future births and
callbacks, but its campaign passed only delayed current-pool snapshots to the
local solver.  On a fixed seed, boundary stratification replaced a 1.98-pixel
continuation with a locally safer 6.85-pixel continuation, yet that trajectory
later met births withheld from planning.  A much wider historical beam also
diverged and incurred collisions.  This was an experimental confounder, not a
license to ignore the hits.

The resolved-stage campaign now closes that join.  A source event at frame
$F$ relative to sensed root $R$ activates at $F-R+1$; direct fires, lasers,
and callback~12/14 share that clock.  Existing bullets receive an exact
callback schedule when composable, future births retain only callbacks that
occur after their allocation, and callback--active-transform interactions use
a conservative reachable-disc fallback.  Automatic aim ranges over every
player position reachable from the coherent root.  The resulting versioned
future is consumed by the delayed prefix, hard preflight, beam expansion,
terminal score, and final recertification, and incomplete coverage makes the
fuzzer case fail.

Integration falsified two timing assumptions independent of hazard geometry.
The old queue paired delayed hazards with the current player and then charged
snapshot lag again.  It also let the beam change action after two frames while
the executor held the selected first action until the next eight-frame planner
tick.  Coherent queued roots and an action hold at least as long as the planner
cadence remove both fictitious branches.  Source inspection found a geometric
underbound as well: transform kind~1 begins at a fixed speed of 5 before
reaching zero, rather than decelerating from descriptor speed.

Across eight fixed quick stages at a matched two-frame cadence, both the
future-aware and blind controllers complete 3,840 frames without a normalized
hit or collision frame.  Thus this corpus establishes coverage, not a survival
advantage.  The future-aware path closes all 1,920 joins but raises the median
per-case p95 solve time from 17.75 to 77.08 ms, largely through 113,119
callback/transform object fallbacks.  It is suitable offline but cannot enter
a 16-ms Wine issue loop.  The next architectural step is a persistent packed
batch and a denser matched-cadence gate, not a spell-specific policy.

A denser 3,600-frame fixed stage does distinguish the information sets.  At
beam width 8, blind planning records five normalized hits and six collision
frames, whereas the complete future join records two and three.  Increasing
width to 24 does not remove the two hits and increases collision duration,
which falsifies beam size as the immediate bottleneck.  That trace instead
revealed a temporal over-approximation: a future callback's maximum speed was
applied from projection frame one as soon as the callback entered the rolling
horizon.  Source order begins that branch only on its due update.  Piecewise
integration corrects the timing, but the rerun records three hits; the old
error was accidentally protective.  We retain the source-faithful correction
and treat the result as evidence for exact callback--transform rollout and
backward viability, not as an empirical policy improvement.

An Easy Final-B physical gate then identified a simpler failure mode that does
not require more global search.  The Practice wrapper had dropped the host's
authority-only option, so thousands of expensive diagnostic corridor queries
ran without constraining any action.  Restoring the option preserves the
global entry point but removes work that has no action authority.  Independently,
the local planner had erased its delay-scaled boundary reserve whenever global
recovery guidance was absent.  That reserve is an actuator property: an input
may remain pending for the full measured delay regardless of whether a global
policy exists.  Making it unconditional under the existing generic option
changes causal boundary roots toward earlier inward continuations while
preserving their collision and terminal hard vectors.  The physical rerun is
therefore a test of two explicit mechanisms---less issue-loop contention and
earlier recoverability preservation.  It completes the same Easy Final-B
scope with nine hits and zero Bomb use, compared with eighteen hits and zero
Bomb use before the corrections.  Bottom-edge pre-hit occupancy and
nonpositive pipeline occupancy each fall by about 45 percent, and the old
corridor-deadline cluster disappears.  Zero global jobs are submitted in the
candidate, confirming that non-authoritative long-horizon work was pure issue-
loop overhead in this gate.  The result is a material generic improvement, not
NMNB: seven residuals reach a modeled losing prefix, while two retain positive
modeled clearance and require sensing/future-birth attribution.  This evidence
supports earlier cheap local viability and a focused observability audit, not
a larger beam or a spell-specific route.

That observability audit found a clock error rather than missing births.  The
pool reader brackets the multi-megabyte bullet copy with the enemy-manager
counter and reads a stable player control root later.  A bracket may therefore
contain slots at every integer age between its endpoints.  The old controller
merged this bracket with newer boss and ECL reads, then used the initial
source-to-hazard offset as a negative bullet projection.  In one retained
contact a point-captured bullet was one update older than the player even
though the merged window reported zero age.  The shipped priority order moves
the player before the bullet manager, whose state-1 update performs the
inclusive AABB test; post-contact state-5 coordinates confirm that order for
both residuals.

The local layer now carries the bullet bracket's discrete age support and
takes the union of its source-faithful trajectories.  The two causal roots
change from positive modeled clearances of 4.16 and 2.27 pixels to collisions;
at the preceding actionable decisions, the issued direction is excluded while
other directions remain viable.  Roughly 79 percent of retained reads have a
singleton support and 21 percent have two ages, so this robustification adds
bounded work instead of another global solve.  Physical hit reduction remains
an experiment, and laser and asynchronously merged enemy epochs are not
claimed by the bullet result.

Development after this correction uses source-driven, complete-stage, and
retained-root differentials as the primary experiment.  Physical Wine trials
are delayed until submissions, completions, version matching, and producer
coverage pass offline on the same Stage~5 roots.  This makes engine semantics
and planner logic deterministic while reserving the expensive physical gate
for residual effects that offline execution cannot establish: process
scheduling, physical sensing cadence, executable numeric behavior, damage
feedback, and realized input delivery.

\section{Conclusion}

The path to fewer hits is not a larger monolithic search.  It is a smaller set
of source-derived transition kernels, explicit uncertainty and coverage,
parallel long-horizon viability, and a bounded low-latency issue layer.  This
architecture makes the VPS useful while preserving a falsifiable boundary
between physical truth, conservative uncertainty, and incomplete prediction.
The source-stateful laboratory makes that boundary executable: it can generate
arbitrarily many long source-closed tests, but it refuses to turn unresolved
producer semantics into fictitious empty space.
